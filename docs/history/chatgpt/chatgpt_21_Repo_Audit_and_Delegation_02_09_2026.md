## Delegation model

### ChatGPT: integration lead / current-state owner

Best suited for work that depends on the latest operational state:

- live server/runtime state, cron, shared Mamay budget and locks;
- PostgreSQL transaction and connection lifecycle reliability;
- integrating, testing, committing and pushing changes;
- reconciling historical notes with current code/DDL/tests/measurements;
- deciding which findings become current baseline;
- sequencing the live analytical pipeline and measuring capacity.

### Claude: bounded review / research engineer

Use Claude aggressively where an independent second engineering pass is valuable and the task can be frozen to a commit/fileset:

- adversarial static review of explicit code at an exact commit;
- DDL/data-contract review: constraints, idempotency, retry semantics, transaction boundaries, provenance/versioning;
- edge-case and test design for relation/event logic;
- prompt/eval review for grounding, evidence and adversarial payloads;
- consolidation of historical engineering notes into neutral ADR/research drafts;
- independent research/comparison that does not require live server state;
- red-team review of a concrete proposed diff before live rollout.

Avoid delegating stale-live tasks without a fresh snapshot: current DB backlog, cron/lock state, live Mamay scheduling, server troubleshooting, or broad architecture redesign.

## Delegation packet contract

Every delegated Claude task should specify:

1. exact branch and commit SHA;
2. bounded file list;
3. current invariants/baseline that must not be re-litigated;
4. precise question;
5. explicit out-of-scope items;
6. required output format: `finding / evidence / severity / minimal fix / verification`.

Claude output is review input, not automatically the project baseline. It is reconciled against current code, tests and measurements before implementation.
