## Чому /6 все одно не пішов у production

Не через повторний провал — через відкриті питання до самої метрики:
- `MERGE_MIN_MEMBER_COVERAGE = 0.60` обрано евристично, без калібрування на human-perevirenomu gold set.
- Підозра, що sparse kNN + complete-link + подальший merge може маскувати fragmentation (об'єднувати те, що виглядає зв'язаним по графу, але не є одним сюжетом по суті), а не тільки лікувати явний giant-bridge.

Тому: **/6 не спростований тим самим тестом, що провалив /5.** Це нова, окрема, ще не прийнята гіпотеза якості, а не відкат через повторний провал.

## Поточний стан production (git-verified 24.09.2026)

`ops/run_signals_snapshot_once.sh` (глобальні Сигнали, живий cron) **не передає `--merge-distance` взагалі**:
```
--core-distance 0.18 \
--related-distance 0.36 \
```
Без цього флагу `algorithm_version()` повертає `ALGORITHM_VERSION = "signals-routing-core-review/4"` — merge-стадія не виконується зовсім, ні `/5`, ні `/6`. Тобто продакшн глобальних Сигналів зараз працює на чистому strict-core, без будь-якого merge.

## Виявлений сьогодні пробіл: немає регрес-тесту на giant-кейс

Пошук по `tests/`/`reporting/` не знайшов жодного тесту, що відтворює саме той failure mode (синтетичний граф з transitive-only bridges, що мав би зловитись coverage/completeness-гейтом). Захист `/6` покритий unit-тестами на власну логіку (coverage, completeness), але немає тесту "цей конкретний історичний інцидент більше не повториться".

## Відкриті питання / рекомендований наступний крок

1. **Регрес-тест на giant-кейс.** Синтетичний unit-тест на `_merge_supported_groups` — граф із transitive-only bridges (без прямої A–C підтримки), що мав давати giant на `/5`-логіці і НЕ повинен давати на `/6`. Дешево, безпечно, не чіпає продакшн-код.
2. **Контрольований експеримент на глобальних Сигналах.** Раз merge зараз повністю вимкнений у проді — увімкнути `--merge-distance` з `/6`-захистом спершу на окремий output-файл (не в живий `signals.latest.json`), порівняти обсяг/якість до-після на поточному 556-джерельному корпусі (старий sweep робився на іншому обсязі джерел). Тільки після цього — рішення про прод.
3. **Калібрування `MERGE_MIN_MEMBER_COVERAGE=0.60`** проти human-gold-set — залишається невирішеним питанням якості, не блокером для (1)-(2).
