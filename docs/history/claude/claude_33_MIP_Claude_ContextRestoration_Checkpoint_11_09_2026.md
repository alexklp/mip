## 2. Архітектурні інваріанти (не переглядати без нової причини)

Джерело: `01_PROJECT_CONTEXT.md`, `02_MIP_Production_Design_v1.6`, підтверджено багаторазово в подальших документах.

- **Content/Occurrence separation** (з v1.3 HLD): `content_items` — канонічний дедуплікований текст; `item_occurrences` — факт публікації в конкретному джерелі. `content_id` — це **лексична dedup-ідентичність, НЕ ідентичність події/публікації** (шаблонні зведення з різних реальних інцидентів можуть схлопнутись в один `content_id` — задокументовано в `claude/26`).
- **4 контури моніторингу:**
  - Контур 1 — об'єкти ДШВ ЗСУ / OPSEC власних підрозділів (`requires_restricted_access=true`);
  - Контур 2 — світовий контекст;
  - Контур 3 — загальнодержавний контекст;
  - Контур 4 — вороже медіа (72 TG-канали, підтверджено списком `Основні_моніторингові_канали_противника.pdf`, дані станом на 30.06.2026).
- `sources.contour_id` — legacy source-level provenance group (в пізніших доках перейменований на `source_group_N` для розрізнення від нереалізованого `content_contour_assignments` як стратегічної content-level осі).
- **LLM НЕ є security boundary** (v1.3 принцип 9.1a) — справжня межа безпеки лежить на рівні ОС/контейнер/мережа, а не на рівні промпту/санітизації.
- **Segment != event != publication.** Segment — суцільний аналітичний фрагмент публікації (може містити 0..N claims/events). Це повторюється як явний застережний інваріант у кожному сегмент-пов'язаному документі (25–30).
- **Human decisions are first-class data** — рішення людини повинні писатись у PostgreSQL з actor identity, не в локальні JSON (принцип 5 `docs/Web_MVP_v1.md`) — за винятком свідомо окремого calibration-інструменту (gold set labeler), який лишається offline за призначенням.

## 7. Signals screen — план і статус

`claude/32` (план на 07.09) визначив 3 типи сигналів:
1. **Хвиля (координоване поширення)** — pgvector cosine + connected components, поріг калібрується (~0.12–0.18 очікування).
2. **Сплеск теми** — log-odds на терміни/біграми, залежить від кешу лем (гейт — якщо немає, тип пропускається).
3. **Контрольний об'єкт (watchlist)** — ILIKE/tsvector по патернах, підтип OPSEC = сутність + geo_hint + слово про наслідки в одному матеріалі, груба v1 без NER.

**Критерій успіху дня 07.09:** ≥10 з 20 карток економлять ручний пошук.

**Чи пройшов цей день і з яким результатом — цій сесії невідомо.** Хендофф 10.09 каже, що робота над Signals UI відбувається на `wip/signals-v1` і фігурує в поточній навігації (`Теми → Сигнали → Джерела`), тобто крок 6 плану (`/signals` як сторінка) ймовірно вже пройдено, але деталі (пороги, типи сигналів що реально запрацювали, чи calibration крок 1 дав очікуване T) — **не підтверджено кодом з цієї сесії**, тільки непрямо через факт наявності пункту меню.
