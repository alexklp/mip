# Технічне завдання до моніторингу інформаційного простору (вихідний ТЗ)

**Джерело:** завантажений користувачем документ (Word), доданий у робочий чат collectors 18.08.2026. Це первинний замовницький ТЗ, який визначає зміст чотирьох контурів моніторингу, згаданих у `02_MIP_Production_Design_v1.6` (`contour_id 1-4`) без розкриття їх наповнення. ## Призначення та сфера застосування

Програма призначена для автоматизованого збору, моніторингу, лінгвістичного аналізу та категоризації текстових, аудіо- та відеоматеріалів у глобальному інфопросторі (Telegram, TikTok, Facebook, Instagram, YouTube, ЗМІ, форуми, ворожі медіа-ресурси).

Головна мета: оперативний аналіз ситуації навколо ДШВ ЗСУ, раннє виявлення інформаційних загроз, координація протидії, контроль репутаційних ризиків.

## Основні функціональні вимоги (верхній рівень, за ТЗ)

- Автоматизований збір: соцмережі, новинні ресурси, блоги, форуми, месенджери (за наявності відкритого доступу); підтримка великої кількості джерел; можливість підключення нових.
- Присвоєння категорії важливості/терміновості; відображення через web-браузер, масштабування (десктоп/планшет/мобільний).
- Моніторинг у реальному часі: оперативне виявлення нових повідомлень, автооновлення, сповіщення про важливі події; контекстний пошук через regex, автоформованих під запити оператора АРМ.
- Пошук/фільтрація: за ключовими словами, хештегами, авторами, мовою, регіоном, часовим інтервалом, типом джерела.
- Аналітична обробка: тематика, тональність (позитив/негатив/нейтрал), інформаційні кампанії, динаміка поширення, аномальна активність.
- Візуалізація: dashboard, графіки, часові шкали, карти поширення, мережеві графи звʼязків між акаунтами.
- Звітність: автоматичні звіти, експорт PDF/Word/Excel, статистика за період, синхронізація при спільній роботі.
- Пошук загроз: дезінформація, координована активність, інформаційні атаки, ботомережі.
- Безпека: автентифікація, захист даних, резервне копіювання.
- Продуктивність: великі обсяги, масштабованість, 24/7, висока швидкість пошуку/аналізу.
- Інтеграція: API, БД, експорт/імпорт.
- ШІ: автоматична класифікація, тематичне групування, прогнозування розвитку кампаній, автовиявлення ІПсО та ознак координованого впливу.

## Словник моніторингових тегів — чотири стратегічні контури

### Контур 1: Об'єкти ДШВ ЗСУ (ЗМІ, Telegram, соцмережі)

- командування ДШВ, командувач; корпуси, окремі бригади, їхні батальйони;
- згадки айдентики (маруновий берет, знак ДШВ, емблеми бригад);
- згадки командирів бригад, начальників штабів, офіцерів, пресофіцерів;
- особовий склад: пошук зниклих безвісти, полонені, списки ПІБ;
- переміщення техніки ДШВ, залізничні ешелони, колони на марші, локації, фото/відео з geo-прив'язкою;
- фішинг під виглядом зборів для ДШВ, шкідливе ПЗ, фейкові чат-боти підрозділів;
- ворожі ІПсО проти ДШВ (вкиди про "оточення", "втрати", "втрату боєздатності");
- внутрішній негатив: критичні публікації військовослужбовців, конфлікти всередині підрозділів, скарги на забезпечення/командування;
- сплески негативних коментарів/критики від родичів, волонтерів, цивільних щодо конкретної бригади;
- резонансні публікації в укр. ЗМІ (розслідування, критичні матеріали).

### Контур 2: Світовий контекст

Пакети військової допомоги, рішення Рамштайну, заяви лідерів НАТО, міжнародні санкції проти РФ, тенденції світового ВПК.

### Контур 3: Загальнодержавний контекст

Події в Україні, рішення Ставки, укази президента, зміни в мобілізації, зведення Генштабу ЗСУ, МОУ, удари по критичній інфраструктурі.

### Контур 4: Моніторинг ворожих медіа

Тези з інтерв'ю Путіна/посадовців РФ щодо України; уражені за добу; мобілізація РФ; міжнародна співпраця РФ; захоплені території; ураження РФ Україною (НПЗ, мости, логістика, техніка, особовий склад); виступи воєнних аналітиків РФ; рух техніки; ІПсО/наративи пропаганди; реакція рос. медіапростору на західну допомогу; внутрішні конфлікти еліт/командування/воєнкорів; суспільні настрої в РФ; стан рос. ВПК; партизанська діяльність/диверсії всередині РФ; іноземні найманці.

**Джерела Контуру 4 (робочий список, 72 Telegram-канали):** окремий файл-довідник, завантажений тим самим повідомленням — стане вхідними даними для наповнення таблиці `sources` (`source_type='telegram'`), коли дійдемо до масового підключення каналів. Найбільші за охопленням: Топор Live (~5M), РИА Новости (~3.3M), Юрий Подоляка (~3M), Mash (~3M), Readovka (~2.5M), далі спадаючий хвіст до ~90K.

## Алгоритм аналізу та категоризації контенту

Кожна публікація проходить обробку за трьома параметрами:
1. **Тональність:** Positive / Neutral / Negative.
2. **Першоджерело:** маркування майданчика (офіційне ЗМІ, ворожий TG-канал, блог тощо, з посиланням).
3. **Віральність (охоплення):** перегляди, репости, коментарі — швидкість поширення хвилі.

Результат — дієвий аналітичний висновок від ШІ з конкретними тезами й доступними фотоматеріалами.

## Як це співвідноситься з поточною реалізацією (нотатка для наступних сесій)

- `contour_id` був свідомо пропущений у мінімальному DDL пілоту (`001_ingestion_pilot.sql`, 18.08.2026) як "не потрібен для доведення механіки content/occurrence". Тепер, коли зміст контурів відомий, повернення `contour_id`/`contours`-довідника в DDL — обґрунтоване наступним кроком, а не питання "може колись".
- Вимога "коментарі" з ТЗ (віральність = перегляди + репости + **коментарі**) — прямий аргумент на користь MTProto-підходу (Telethon) для Telegram-collector'а замість `t.me/s/`-preview: коментарі живуть в discussion-групі, прив'язаній до каналу, і без клієнтської сесії недоступні.
- Розширена функціональність ТЗ (dashboard, мережеві графи, ІПсО-детекція, прогнозування) — це прямий production scope, значно ширший за поточний Technical Pilot. Не є задачею collectors-етапу; фіксується тут як target-стан, до якого рухаємось поступово через уже прийнятий цикл Data Model → DDL → LLD → pilot → measurements.
